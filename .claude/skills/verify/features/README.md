# corerope.space feature map

`../features.json` is generated by `featuremap` and never edited by hand. The
files here hold the recipes. Each one declares the ids it covers in a
`<!-- covers: -->` line, and `featuremap check` fails when an id has no recipe or
a recipe covers an id that no longer exists.

## Preconditions

The site built and served on port 4317 per ../SKILL.md. Nothing else: no accounts, no database, no
secrets. The data recipes need `.venv` (`make venv`). Only deploy.sh touches anything outside this
machine (Vercel, with VERCEL_TOKEN from .env); run it only to ship, never as a probe.

## Proof rules

- Drive the path a user takes. Mocks count only at a boundary production also has
  (a third-party API), never around the code being checked.
- A recipe lists every entry point. Proving one convenient entry point does not
  prove the others.
- An unreachable entry point is reported with its missing precondition. It is not
  counted as verified.
- A number on a page is right only if it matches the research file or `data/*.json` it came from.
  Check the figure's provenance line (Data, Script, From) and compare.

## Areas

- [home](home.md): the story: the 3D core rope hero, headline numbers, six chapters, three scroll-driven 3D scenes.
- [survey](survey.md): /survey (and the old /baseline, /levers): baselines, four terms, lever families, budget, odds.
- [design](design.md): /design (and the old /design/<slug>): seven parts, each with its risk, test and evidence.
- [cost-model](cost-model.md): /cost-model, the interactive calculator, the model's charts and the Amdahl control.
- [experiments](experiments.md): /experiments (and the old /risks): results re-run, roadmap, risks, gaps, prior art.
- [research](research.md): /research and every research file rendered whole under /research/[slug].
- [meta](meta.md): icon, touch icon, share card, manifest, robots, sitemap, the 404 page.
- [data](data.md): `make data`, `make synth`, `make check`: the pipeline that writes data/ and
  reproduces RESULTS.md.
- [deploy](deploy.md): tools/site/deploy.sh, Vercel and the live domains.

## Entry contract

Each area file has: an H1, a one-line summary, a `<!-- covers: ids -->` line, then
exactly these sections: `## Sub-features`, `## How to reach it`, `## How to check
it`, `## Gotchas`. Keep it short enough to run without reading source. Split a
file once a section needs its own preconditions.
